Fix: quiz option state leaking between questions

ChoiceQuestionBody/SocraticQuestionBody remembered state (selectedIndex,
revealed, submitted) was keyed to call-site position, not to the
question being shown. Since QuizScreen reuses the same call site for
every question in sequence, answering one true/false or multiple-choice
question left it "revealed" and locked, and the next question rendered
as already-answered/disabled.

Fix: wrap the QuestionBody call in key(question.id) so Compose treats
each question as a fresh subtree and resets per-question remembered
state when currentIndex advances.
