Dictionary v2.0: migrate to indexed SQLite, fix slow open + ranking

Per feedback: the dictionary was slow to open, and typing an exact
word didn't surface it reliably in the results.

Root causes:
- SwahiliDictionaryRepository.load() parsed a 2MB JSON file into
  ~16,000 Kotlin objects synchronously on the UI thread the first
  time the dialog opened, visibly freezing the app.
- The search filter checked headword/definition/English with a plain
  `contains()` and no ranking or cap, so an exact headword match could
  be buried under unrelated substring hits inside long definition text.

Fix: migrate to a pre-built, pre-indexed SQLite database.

- Built assets/swahili_dictionary.db (2.36MB) from the existing
  16,156-entry dataset via a one-off Python script: table `entries`
  (headword, headword_lower, pos, def_sw, en) with a B-tree index on
  headword_lower. Removed the old swahili_dictionary.json asset.
- Rewrote data/SwahiliDictionaryRepository.kt:
  - Copies the asset DB into the app's private database directory on
    first use (SQLite can't open a file directly inside the APK), then
    opens it read-only via a cached SQLiteOpenHelper connection.
  - All reads (`browsePreview`, `search`, `totalCount`) are suspend
    functions running on Dispatchers.IO -- nothing is parsed into an
    in-memory List anymore.
  - `search()` runs 4 ranked tiers in priority order (exact headword ->
    starts-with -> headword-contains -> definition/English-contains),
    de-duplicated, capped at 50 results -- the exact word you typed now
    always sorts first.
  - Added `warmUp()` to open/copy the DB ahead of time.
- ui/SwahiliDictionaryDialog.kt: replaced the eager in-memory
  `remember { load() }` + `filter {}` with LaunchedEffect-driven async
  queries, a loading spinner while a query is in flight, and totalCount
  fetched once instead of allEntries.size.
- ui/HomeScreen.kt: added a LaunchedEffect(Unit) that calls
  SwahiliDictionaryRepository.warmUp() as soon as Home appears, so the
  DB connection is typically already open by the time the student taps
  "Kamusi".
- Chose plain indexed columns + tiered LIKE queries over SQLite's FTS5
  full-text search extension, since FTS5 availability depends on the
  device's bundled SQLite build and isn't guaranteed across all
  minSdk-24-and-up devices/vendors; at ~16,000 rows plain indexes are
  comfortably fast either way.
